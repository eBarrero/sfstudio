# PBI-009: Cliente API relativo y contratos tipados

- Estado: Propuesta
- Prioridad: Must
- Tamaño relativo: M
- Dependencias: PBI-005, PBI-008

## Historia de usuario

Como usuario desplegado en Render, quiero que el frontend llame al mismo host y entienda de forma uniforme los errores de conexión.

## Objetivo

Eliminar localhost del bundle y centralizar un cliente HTTP tipado para workspace, metadata y query.

## Alcance

- Usar base URL relativa /api/v1 por defecto.
- Permitir override solo mediante variable Vite validada.
- Crear tipos de respuesta y ApiError.
- Enviar credentials y correlationId según contrato.
- Traducir REAUTH_REQUIRED y expiración de workspace.

## Criterios de aceptación

- El bundle de producción no contiene http://localhost:3000.
- Desarrollo funciona mediante proxy Vite.
- Todos los servicios usan el cliente compartido.
- Errores HTTP conservan code y correlationId sin depender del texto.
- Una respuesta 401 REAUTH_REQUIRED activa la acción apropiada.

## Pruebas requeridas

- Unitarias del cliente con fetch simulado.
- Build y búsqueda que descarta localhost.
- Integración de errores 400, 401, 404 y 500.

## Fuera de alcance

- GraphQL.
- SDK generado automáticamente.

## Definition of Done

- Criterios cubiertos por pruebas.
- Componentes accesibles mediante teclado.
- Ratón y comando comparten ActionId y caso de uso.
- Documentación de comandos actualizada.
