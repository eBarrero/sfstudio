# PBI-010: Selector y contexto visible de organización

- Estado: Implementada; pendiente de validación en CI
- Prioridad: Must
- Tamaño relativo: L
- Dependencias: PBI-009

## Historia de usuario

Como usuario con varias orgs, quiero saber siempre dónde estoy trabajando y alternar sin confundir Integración, UAT o Producción.

## Objetivo

Rediseñar el gestor de conexiones como selector de org activa con estado inequívoco.

## Alcance

- Mostrar alias, organizationId abreviado, usuario, entorno y estado.
- Seleccionar una org activa por OrgKey.
- Acciones conectar, reconectar y cerrar.
- Indicador persistente de contexto activo junto al explorador y consulta.
- No usar color como única señal.

## Criterios de aceptación

- Con dos orgs conectadas solo una figura como activa.
- Cambiar de activa no cierra ni reemplaza conexiones.
- Cada consulta/exploración muestra el destino actual.
- CONNECTED, CONNECTING, REAUTH_REQUIRED y ERROR son distinguibles y accesibles.
- Alias duplicados no seleccionan la org equivocada.

## Pruebas requeridas

- Componentes con todos los estados.
- Accesibilidad de teclado y lector básico.
- Integración del selector con store.

## Fuera de alcance

- Comparación de dos orgs.
- Preferencias visuales avanzadas.

## Definition of Done

- Criterios cubiertos por pruebas.
- Componentes accesibles mediante teclado.
- Ratón y comando comparten ActionId y caso de uso.
- Documentación de comandos actualizada.

## Evidencia de implementación

- `POST /api/v1/workspace/active-org` selecciona solo un `OrgKey` conocido y conectado; conserva todos los drivers. Devuelve errores públicos para clave inválida, org ajena y conexión perdida.
- El gestor muestra alias, ID abreviado con ID completo accesible, usuario, entorno y los cuatro estados con texto. Botones nativos permiten conectar, seleccionar, desconectar y reautenticar mediante teclado. `aria-pressed` y el texto **Organización activa** identifican la selección sin depender del color.
- El destino aparece junto al explorador y en el panel de consulta/resultados. Cambiar de org limpia el modelo SOQL y resultados anteriores; respuestas tardías de esquema y consultas no sustituyen el contexto nuevo.
- El botón **Usar** y el comando `Select_org_<organizationId>_<userId>` comparten `org.use`, `OrgKey` y la misma acción del store. Pruebas cubren alias duplicados, estados, foco de teclado, alternancia y contrato HTTP.
