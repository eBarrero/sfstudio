# PBI-020: Resultados efímeros y paridad de ejecución

- Estado: Propuesta
- Prioridad: Must
- Tamaño relativo: M
- Dependencias: PBI-019, PBI-011

## Historia de usuario

Como usuario, quiero revisar resultados sin que SF Studio cree una copia permanente de los datos de negocio.

## Objetivo

Asegurar que los resultados viven solo en memoria y que ejecución, paginación y limpieza tienen comandos gemelos.

## Alcance

- Store de resultados en memoria por ejecución.
- Limpiar al cerrar workspace o mediante acción explícita.
- No escribir resultados en IndexedDB, localStorage, MongoDB ni logs.
- Acciones query run, query next, query cancel y query clear.
- Mejorar tabla para null, boolean, relaciones y columnas variables.

## Criterios de aceptación

- Recargar la página elimina resultados salvo política explícita futura.
- Inspeccionar almacenamientos no muestra registros Salesforce.
- Cerrar workspace limpia consultas y cursores.
- Botones y comandos producen el mismo estado.
- Los errores no incluyen filas ni datos sensibles.

## Pruebas requeridas

- Espía sobre adaptadores de persistencia.
- Componentes con resultados anidados y null.
- E2E ejecutar, paginar y limpiar por UI y comando.

## Fuera de alcance

- Historial persistente.
- Exportación masiva automática.

## Definition of Done

- Casos positivos y negativos automatizados.
- Solo SELECT está permitido en esta fase.
- Resultados y query text sensible no se persisten ni registran.
- UI y comandos comparten acciones.
