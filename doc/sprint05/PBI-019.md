# PBI-019: Destino explícito, límites y paginación

- Estado: Propuesta
- Prioridad: Must
- Tamaño relativo: L
- Dependencias: PBI-018, PBI-010

## Historia de usuario

Como usuario con varias orgs, quiero saber dónde se ejecutará una consulta, limitar su impacto y navegar resultados grandes.

## Objetivo

Integrar el dominio SOQL con el contexto multi-org y nextRecordsUrl de Salesforce.

## Alcance

- Mostrar OrgKey/alias destino junto al editor y confirmación.
- Límite por defecto y máximo configurable por política.
- Continuación paginada mediante cursor opaco asociado a workspace/org.
- Cancelar petición en curso al cambiar de contexto.
- Estados loading, partial, done y error.

## Criterios de aceptación

- Nunca se ejecuta si el destino no está visible y conectado.
- El límite por defecto aparece en el SOQL o política de ejecución.
- Cambiar de org no reutiliza cursor de otra.
- Páginas adicionales mantienen columnas y orden.
- No se realizan varias cargas simultáneas por doble clic/comando.

## Pruebas requeridas

- Integración de primera página y continuation.
- Cursor de otra org rechazado.
- Cambio de destino durante carga.

## Fuera de alcance

- Descargar millones de filas.
- Bulk API.

## Definition of Done

- Casos positivos y negativos automatizados.
- Solo SELECT está permitido en esta fase.
- Resultados y query text sensible no se persisten ni registran.
- UI y comandos comparten acciones.
