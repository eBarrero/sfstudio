# PBI-018: Endpoint POST de consulta de solo lectura

- Estado: Propuesta
- Prioridad: Must
- Tamaño relativo: L
- Dependencias: PBI-017, PBI-007

## Historia de usuario

Como responsable del equipo, quiero que la API solo ejecute consultas autorizadas de lectura y no exponga SOQL en URLs o logs.

## Objetivo

Reemplazar la ruta GET codificada por un contrato POST con org destino, consulta y límites.

## Alcance

- POST /api/v1/query con orgKey y query.
- Comprobar que orgKey pertenece al workspace y está CONNECTED.
- Validar operación SELECT y límites máximos.
- Body size, timeout y rate limit razonables.
- Respuesta y errores tipados; no registrar query completa por defecto.

## Criterios de aceptación

- La API rechaza org ajena, desconectada o inexistente.
- Rechaza comandos no SELECT y consultas por encima de límites.
- La consulta no aparece en path, access log ni referrer.
- Timeout/cancelación devuelve código estable.
- El endpoint anterior queda retirado o deprecado sin ambigüedad.

## Pruebas requeridas

- Integración con driver falso y matriz de rechazos.
- Prueba de límite, timeout y REAUTH_REQUIRED.
- Contrato de respuesta.

## Fuera de alcance

- DML, Tooling API o Anonymous Apex.
- Persistir historial en servidor.

## Definition of Done

- Casos positivos y negativos automatizados.
- Solo SELECT está permitido en esta fase.
- Resultados y query text sensible no se persisten ni registran.
- UI y comandos comparten acciones.
