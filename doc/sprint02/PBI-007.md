# PBI-007: Registro de conexiones por workspace

- Estado: Implementada; pendiente de validación en CI y con MongoDB real
- Prioridad: Must
- Tamaño relativo: L
- Dependencias: PBI-005, PBI-006

## Historia de usuario

Como miembro del equipo, quiero mantener varias orgs abiertas para alternar y compararlas durante una sesión.

## Objetivo

Reemplazar los singletons globales conceptuales por un registro de conexiones aislado por workspace y OrgKey.

## Alcance

- Gestionar Map<WorkspaceId, Map<OrgKey, Connection>>.
- Añadir/listar/consultar conexiones por workspace.
- Evitar que una conexión de un workspace sea visible desde otro.
- Definir limpieza por expiración y cierre.
- Exponer GET /api/v1/workspace con orgs conocidas y estados.

## Criterios de aceptación

- Un workspace mantiene dos conexiones activas simultáneamente.
- La conexión a la segunda org no reemplaza la primera.
- Una cookie de otro workspace no accede a esas conexiones.
- La limpieza elimina conexiones expiradas y libera recursos.
- La API nunca serializa access o refresh tokens.

## Pruebas requeridas

- Unitarias del registro multi-workspace.
- Integración con dos drivers falsos.
- Aislamiento entre dos workspaces concurrentes.

## Fuera de alcance

- Escalado a varias instancias del servidor.
- Persistir conexiones activas.

## Definition of Done

- Criterios demostrados con pruebas automatizadas o evidencia manual indicada.
- Contratos y errores públicos documentados.
- Ningún token aparece en MongoDB, respuestas o logs.

## Evidencia de implementación

- `ConnectionRegistry` mantiene los drivers en `Map<WorkspaceId, Map<OrgKey, driver>>`. Añadir una segunda org no reemplaza la primera; la rotación de cookie tras OAuth traslada ambas.
- `GET /api/v1/workspace` reconcilia las orgs conocidas con el registro y devuelve `CONNECTED` o `REAUTH_REQUIRED` según la disponibilidad real del driver. No serializa el driver, access token ni refresh token.
- Los endpoints de lectura comprueban pertenencia al workspace y devuelven `401 REAUTH_REQUIRED` con `{ error: { code, message, correlationId } }` si falta el driver. Una cookie de otro workspace no obtiene la conexión aunque conozca el `OrgKey`.
- El registro libera drivers mediante `dispose()` al sustituir, retirar una org o expirar la sesión. Hay limpieza al acceder y barrido periódico cada minuto. El cierre de una sesión elimina su registro; los workspaces y registros no se persisten como conexiones activas.
- La migración dirigida elimina solo el índice único heredado `WorkspaceSession.user_1`, permitiendo sesiones concurrentes del mismo usuario. `sessionId_1` y el índice TTL permanecen. La guía de desarrollo indica el permiso MongoDB necesario.
- Pruebas unitarias del registro, integración de dos drivers falsos con rotación, aislamiento de dos workspaces, contrato HTTP de cookies y ausencia de tokens en la respuesta. La validación con MongoDB real sigue pendiente de un entorno controlado.
