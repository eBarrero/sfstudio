# PBI-007: Registro de conexiones por workspace

- Estado: Propuesta
- Prioridad: Must
- Tamaño relativo: L
- Dependencias: PBI-005, PBI-006

## Historia de usuario

Como miembro del equipo, quiero mantener varias orgs abiertas para alternar y compararlas durante una sesión.

## Objetivo

Reemplazar los singletons globales conceptuales por un registro de conexiones aislado por workspace y OrgKey.

## Alcance

- Gestionar Map<WorkspaceId, Map<OrgKey, Connection>>.
- Añadir/listar/consultar conexiones por workspace.
- Evitar que una conexión de un workspace sea visible desde otro.
- Definir limpieza por expiración y cierre.
- Exponer GET /api/v1/workspace con orgs conocidas y estados.

## Criterios de aceptación

- Un workspace mantiene dos conexiones activas simultáneamente.
- La conexión a la segunda org no reemplaza la primera.
- Una cookie de otro workspace no accede a esas conexiones.
- La limpieza elimina conexiones expiradas y libera recursos.
- La API nunca serializa access o refresh tokens.

## Pruebas requeridas

- Unitarias del registro multi-workspace.
- Integración con dos drivers falsos.
- Aislamiento entre dos workspaces concurrentes.

## Fuera de alcance

- Escalado a varias instancias del servidor.
- Persistir conexiones activas.

## Definition of Done

- Criterios demostrados con pruebas automatizadas o evidencia manual indicada.
- Contratos y errores públicos documentados.
- Ningún token aparece en MongoDB, respuestas o logs.
