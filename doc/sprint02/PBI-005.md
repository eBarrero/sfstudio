# PBI-005: Identidad estable de organización y contratos multi-org

- Estado: Propuesta
- Prioridad: Must
- Tamaño relativo: L
- Dependencias: PBI-004

## Historia de usuario

Como usuario, quiero que SF Studio distinga correctamente cada organización y usuario aunque sus alias o dominios sean parecidos.

## Objetivo

Introducir OrgKey y DTOs explícitos para workspace, organización configurada y conexión activa.

## Alcance

- Definir OrgKey a partir de organizationId y userId.
- Separar alias, instanceUrl, loginHost, environmentKind y estado de conexión.
- Sustituir índices de array como identidad externa por OrgKey.
- Versionar los contratos JSON de workspace y conexión.
- Diseñar migración o invalidación segura de documentos Mongo antiguos.

## Criterios de aceptación

- Dos conexiones con alias iguales mantienen identidades distintas.
- Cambiar un alias no invalida caché ni conexión.
- Los endpoints nunca usan la posición del array como identificador persistente.
- El contrato distingue CONNECTED, REAUTH_REQUIRED, CONNECTING y ERROR.
- Los datos antiguos se migran o fuerzan a reconectar de forma controlada.

## Pruebas requeridas

- Unitarias de construcción y comparación de OrgKey.
- Contrato de serialización del workspace.
- Migración con documento anterior.

## Fuera de alcance

- Alias compartidos entre usuarios.
- Comparación de esquemas.

## Definition of Done

- Criterios demostrados con pruebas automatizadas o evidencia manual indicada.
- Contratos y errores públicos documentados.
- Ningún token aparece en MongoDB, respuestas o logs.
