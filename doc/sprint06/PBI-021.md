# PBI-021: Orquestación de pareja de snapshots

- Estado: Propuesta
- Prioridad: Must
- Tamaño relativo: M
- Dependencias: PBI-015, PBI-016

## Historia de usuario

Como usuario, quiero comparar dos orgs usando snapshots tomados y etiquetados de forma coherente.

## Objetivo

Definir ComparisonSession y adquirir/congelar origen y destino antes de calcular diferencias.

## Alcance

- Seleccionar sourceOrgKey y targetOrgKey distintos.
- Verificar permisos y disponibilidad de ambas conexiones/snapshots.
- Registrar apiVersion, usuario y fetchedAt de cada lado.
- Opción actualizar ambos antes de empezar.
- Congelar referencias durante la comparación.

## Criterios de aceptación

- No se inicia comparación con la misma org en ambos lados.
- La sesión conserva exactamente las versiones seleccionadas.
- Si una org requiere login se devuelve REAUTH_REQUIRED indicando cuál.
- Diferente apiVersion produce advertencia o bloqueo según política.
- Refresh posterior no cambia silenciosamente una comparación abierta.

## Pruebas requeridas

- Creación válida e inválida de ComparisonSession.
- Reauth de un solo lado.
- Snapshots con versiones distintas.

## Fuera de alcance

- UI final de comparación.
- Persistir comparaciones en servidor.

## Definition of Done

- Resultado determinista, serializable y versionado.
- Pruebas con fixtures anonimizados cubren before/after.
- El dominio no importa React, Zustand, IndexedDB ni clientes HTTP.
- Rendimiento medido con un snapshot representativo.
