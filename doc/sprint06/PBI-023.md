# PBI-023: Diff de campos, propiedades y picklists

- Estado: Propuesta
- Prioridad: Must
- Tamaño relativo: L
- Dependencias: PBI-022

## Historia de usuario

Como usuario, quiero entender las diferencias de definición de cada campo entre dos orgs.

## Objetivo

Comparar campos por objeto/API name incluyendo propiedades relevantes y valores de picklist.

## Alcance

- Campos ADDED, REMOVED, MODIFIED y UNCHANGED.
- Tipo, longitud, precisión, escala, nillable, unique, externalId y otras propiedades acordadas.
- Picklists como conjuntos ordenados por value con active/default.
- Descripción/label configurables como cambio funcional o informativo.
- Ruta estable object.field.property para cada diferencia.

## Criterios de aceptación

- Cambio de tipo o longitud se identifica con before/after.
- Reordenar picklist sin cambio semántico no produce falso positivo.
- Añadir, retirar o desactivar valor sí se refleja.
- Campos inexistentes no producen cascadas de propiedades redundantes.
- El resultado es serializable y determinista.

## Pruebas requeridas

- Matriz por propiedad.
- Picklists reordenadas y modificadas.
- Campos compuestos/referencia y valores null.

## Fuera de alcance

- Comparar FLS por perfil.
- Transformar una org para igualarla.

## Definition of Done

- Resultado determinista, serializable y versionado.
- Pruebas con fixtures anonimizados cubren before/after.
- El dominio no importa React, Zustand, IndexedDB ni clientes HTTP.
- Rendimiento medido con un snapshot representativo.
