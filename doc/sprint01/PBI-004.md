# PBI-004: OAuth state seguro y logging con redacción

- Estado: Propuesta
- Prioridad: Must
- Tamaño relativo: L
- Dependencias: PBI-003

## Historia de usuario

Como responsable de seguridad, quiero que cada callback OAuth pertenezca al workspace que lo inició y que los logs no expongan credenciales.

## Objetivo

Usar un state criptográfico de un solo uso y establecer reglas de redacción de logs.

## Alcance

- Crear y guardar nonce OAuth asociado a workspace, destino y expiración.
- Leer state desde req.query y validarlo antes de intercambiar code.
- Consumir state una sola vez.
- Introducir logger estructurado con correlationId.
- Redactar cookies, code, tokens, secretos, URLs de autorización y PII sensible.

## Criterios de aceptación

- Un callback sin state, expirado, repetido o ajeno responde 400/401 sin llamar a Salesforce.
- Un state válido solo puede consumirse una vez.
- Los logs permiten correlacionar el flujo sin mostrar code, cookie o token.
- Los errores al cliente usan código estable y mensaje no sensible.

## Pruebas requeridas

- Unitarias de generación, expiración y consumo.
- Integración de callbacks válido, inválido y replay.
- Test que inspecciona logs y confirma redacción.

## Fuera de alcance

- Persistencia de refresh tokens.
- Extensión de navegador.

## Definition of Done

- Todos los criterios de aceptación están demostrados.
- Las pruebas nuevas pasan en CI.
- No se introducen secretos ni datos personales en fixtures o logs.
- La documentación afectada queda actualizada.
