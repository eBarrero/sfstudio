# PBI-003: Sesión de workspace segura

- Estado: Implementada; pendiente de validación en GitHub Actions
- Prioridad: Must
- Tamaño relativo: L
- Dependencias: PBI-002

## Historia de usuario

Como usuario interno, quiero que mi workspace no pueda ser adivinado ni suplantado por otro usuario.

## Objetivo

Reemplazar el sessionId numérico/Base64 por un identificador criptográfico y una sesión con expiración.

## Alcance

- Generar IDs con crypto.randomUUID o 128 bits aleatorios.
- Persistir solo el estado mínimo del workspace y su expiración.
- Cookie httpOnly, secure en producción, sameSite, path y maxAge.
- Rotar el ID después de autenticación.
- Eliminar sessionId de DTO públicos salvo necesidad demostrada.

## Criterios de aceptación

- No se utiliza Math.random para IDs de sesión.
- Modificar manualmente la cookie produce 401 y no accede a otra sesión.
- La cookie de producción tiene Secure, HttpOnly y SameSite.
- Una sesión expirada se elimina y requiere iniciar un nuevo workspace.
- La rotación invalida el identificador anterior.

## Pruebas requeridas

- Unitarias de generación y expiración.
- Integración de cookie ausente, válida, manipulada y expirada.

## Fuera de alcance

- Persistir tokens Salesforce.
- SSO corporativo de SF Studio.

## Definition of Done

- Todos los criterios de aceptación están demostrados.
- Las pruebas nuevas pasan en CI.
- No se introducen secretos ni datos personales en fixtures o logs.
- La documentación afectada queda actualizada.

## Evidencia de implementación

Validación local realizada el 25 de octubre de 2026:

- Los identificadores son UUID v4 generados mediante `crypto.randomUUID`; no quedan IDs de sesión basados en `Math.random`.
- La colección `WorkspaceSession` persiste únicamente UUID, referencia al usuario y `expiresAt`, con índice TTL.
- La cookie de producción incluye `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/` y `Max-Age=28800`.
- Las pruebas HTTP cubren cookie ausente, válida, malformada, manipulada con UUID desconocido y expirada.
- La rotación elimina el UUID anterior de memoria, actualiza MongoDB y mueve el pool de conexiones al UUID nuevo.
- El DTO público no contiene `sessionId` y los errores devuelven `401 SESSION_INVALID` sin revelar identificadores.
- `npm test`: 22 pruebas de API y 2 pruebas de frontend superadas.
- `npm run typecheck`, `npm run lint`, `npm run build` y `npm run audit`: código 0.
- La ejecución alojada de GitHub Actions queda pendiente del primer `push` o `pull_request` que incluya este commit.
