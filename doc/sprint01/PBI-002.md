# PBI-002: Configuración validada y endpoints de salud

- Estado: Implementada; pendiente de validación en GitHub Actions
- Prioridad: Must
- Tamaño relativo: M
- Dependencias: PBI-001

## Historia de usuario

Como operador interno, quiero saber si la API está correctamente configurada y lista para atender peticiones.

## Objetivo

Validar variables al arrancar y separar liveness de readiness sin revelar valores sensibles.

## Alcance

- Crear un módulo tipado de configuración.
- Fallar rápido si faltan CLIENT_ID, CLIENT_SECRET, REDIRECT_URI o MONGO en el entorno correspondiente.
- Añadir GET /health y GET /ready.
- Readiness comprueba conexión MongoDB; health solo vida del proceso.
- Documentar configuración local y Render.

## Criterios de aceptación

- La API no arranca en producción si falta una variable obligatoria.
- GET /health responde 200 sin depender de Salesforce.
- GET /ready responde 200 solo cuando MongoDB está disponible.
- Ninguna respuesta o log de configuración muestra secretos.

## Pruebas requeridas

- Unitarias de parsing por entorno.
- Integración de health/readiness con Mongo disponible y no disponible.

## Fuera de alcance

- Monitorización externa.
- Métricas de negocio.

## Definition of Done

- Todos los criterios de aceptación están demostrados.
- Las pruebas nuevas pasan en CI.
- No se introducen secretos ni datos personales en fixtures o logs.
- La documentación afectada queda actualizada.

## Evidencia de implementación

Validación local realizada el 25 de octubre de 2026:

- El arranque compilado con `ENV=PROD` y sin configuración obligatoria termina con código 1 antes de abrir el puerto; el error solo enumera los nombres de variables ausentes.
- `GET /health` devuelve 200 sin invocar la sonda de MongoDB.
- `GET /ready` devuelve 200 con la sonda disponible y 503 cuando no está disponible o lanza un error.
- Las respuestas de readiness no contienen detalles de conexión.
- `npm test`: 12 pruebas de API y 2 pruebas de frontend superadas.
- `npm run typecheck`, `npm run lint`, `npm run build` y `npm run audit`: código 0.
- La ejecución alojada de GitHub Actions queda pendiente del primer `push` o `pull_request` que incluya este commit.
