# PBI-015: Expiración, refresco y consistencia de snapshots

- Estado: Propuesta
- Prioridad: Must
- Tamaño relativo: M
- Dependencias: PBI-014, PBI-011

## Historia de usuario

Como usuario, quiero saber de cuándo es la estructura mostrada y actualizarla después de un despliegue Salesforce.

## Objetivo

Añadir TTL, stale-while-revalidate controlado y refresco manual por org.

## Alcance

- Guardar fetchedAt y expiresAt.
- Mostrar fecha/estado vigente, obsoleto o actualizando.
- Acción refresh metadata con botón y comando.
- Invalidar por org, usuario, apiVersion y schemaVersion.
- Evitar reemplazar un snapshot usado activamente por una comparación sin avisar.

## Criterios de aceptación

- Una entrada vigente se usa inmediatamente.
- Una entrada expirada se marca y actualiza según política.
- El usuario puede forzar refresh por UI y comando.
- El fallo de refresh conserva el último snapshot con aviso.
- Dos snapshots de una comparación permanecen congelados durante esa comparación.

## Pruebas requeridas

- Reloj falso para TTL.
- Refresh concurrente deduplicado.
- Fallo remoto conservando stale snapshot.

## Fuera de alcance

- Webhooks de cambios metadata.
- Actualización en tiempo real.

## Definition of Done

- Criterios automatizados y demostrados con dos orgs diferentes.
- No quedan claves de caché basadas solo en alias o dbName.
- No se persisten tokens ni resultados de consulta.
- Acciones nuevas tienen entrada visual y comando.
