# PBI-013: Modelo normalizado de snapshot de metadatos

- Estado: Propuesta
- Prioridad: Must
- Tamaño relativo: L
- Dependencias: PBI-005, PBI-009

## Historia de usuario

Como motor de exploración y comparación, quiero una representación estable del esquema independiente de la respuesta cruda de Salesforce.

## Objetivo

Definir snapshots versionados de org, objetos, campos, picklists y relaciones.

## Alcance

- Separar tipos Salesforce crudos de tipos de dominio.
- Crear MetadataSnapshot con orgKey, apiVersion, locale, fetchedAt y schemaVersion.
- Normalizar índices por API name y claves deterministas.
- Preservar propiedades requeridas para exploración y comparación.
- Eliminar Map u otros valores no serializables del formato persistido.

## Criterios de aceptación

- El mismo describe produce el mismo snapshot ordenado.
- El snapshot puede serializarse y restaurarse sin pérdida funcional.
- Campos y relaciones se identifican por API name, no por posición.
- Snapshots de usuarios distintos no comparten clave.
- Cambiar schemaVersion obliga a migrar o invalidar.

## Pruebas requeridas

- Golden tests con fixtures anonimizados.
- Round-trip serialización/restauración.
- Orden distinto de Salesforce produce snapshot equivalente.

## Fuera de alcance

- Comparar snapshots.
- Persistir datos de registros.

## Definition of Done

- Criterios automatizados y demostrados con dos orgs diferentes.
- No quedan claves de caché basadas solo en alias o dbName.
- No se persisten tokens ni resultados de consulta.
- Acciones nuevas tienen entrada visual y comando.
